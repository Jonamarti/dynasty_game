## Goal

Know exactly where M16 starts, so that every later "before and after" has a
fixed "before", and so nobody mistakes an inherited failure for their own.

## Background

`docs/m15_closeout_20261016.md` records the state at `0.15.160-alpha`:
matrix of 43 scenarios, 17 clean, 1,810/1,928 applicable checks, 118 failures;
unit suite 320 files, 2,339 passed, 1 skipped; e2e 186/186 cases ok but the
runner hangs at teardown (tool bug T4/E15, fixed in 1.2). Open M15 gates:
`lean` survival ≥ 60.9 %, recovery ≥ 50 %, `answered` ≥ 90 %, fire in `century`
≥ 50 %, compact correspondence, 32c peoples (`farming-spreads`,
`states-arise` 0/20), 15c spoilage still off. **The owner accepted all of
these as the M16 starting point.** They are revisited in 10.2, not before.

## Steps

1. Record the M15 closing commit (`git log -1`) and `package.json` version.
2. Run and save each output under `artifacts/verification/m16-baseline/`:
   - `npm.cmd run typecheck`
   - `npm.cmd test -- --maxWorkers=1 --testTimeout=15000`
   - `npm.cmd run sim:check:all -- --verbose`
   - `npm.cmd run e2e` (if it hangs after the last case, record the case
     count and interrupt; that is T4, not a failure)
   - `npm.cmd run profile:systems`
3. One at a time (R27): `npm.cmd run sim:seeds -- --scenario band --seeds 20`
   and `npm.cmd run sim:seeds -- --scenario century --seeds 20`.
4. Create `docs/m16/baseline.md` with:
   - commit, version, date, machine;
   - number of unit test files/tests/skips and the list of failing tests;
   - for every scenario of the matrix: pass/total and **the names of the
     failing checks** (this list is what R21 refers to);
   - `band` and `century` cohort: mean survival, collapses, mean steps/s;
   - ms per step with ~30 and ~300 people (from `profile:systems`; if it does
     not report 300, write what it reports and leave 300 to 1.8);
   - a table "M15 open gates accepted as baseline" copied from the closeout
     table with their last measured value;
   - a table of what M15 shipped that M16 cards rely on (fill from
     `docs/m15_plan.md` and the changelog):
