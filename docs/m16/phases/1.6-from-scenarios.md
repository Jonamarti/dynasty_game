# M16 1.6 — Short scenarios that start from a fixture

| | |
|---|---|
| Stage / step | 1 / 9 |
| Switch | none |
| Changes the world | no |
| Depends on | 1.5 |

## Goal

Area checks in minutes, not tens of minutes, without losing the old scenarios.

## Steps

1. In `tools/simcheck.ts`, add to `interface Scenario` (~l. 75) two optional
   fields: `world?: string` (fixture name) and `areas?: string[]`.
2. Where a scenario is run: if `world` is set, start from `loadWorld(world)`.
3. **Add** new scenarios next to the old ones; replace none. Name = old name +
   `-from` (e.g. `labour-from`). Each runs at most a third of the original steps.
4. Tag every scenario, old and new, with areas from: `foresight`, `assembly`,
   `objects`, `bands`, `discovery`, `player`, `world`, `shelter`, `base`.
5. Mark an old scenario `slow: true` **only** after its `-from` twin has given
   the same applicable checks across two weeks of commits — not in this phase.

## Done when

At least one `-from` scenario per fixture, each under a third of the original
steps, every scenario tagged.

## Watch out

`n/a` is not a pass: if a `-from` scenario cannot exercise a check its original
did, write that in the scenario's description. Tooling only: no version bump.
