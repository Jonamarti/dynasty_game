# M16 14.8 — Daily wear and repair: upkeep as the natural limit

| | |
|---|---|
| Stage / step | 3 / 47 |
| Switch | none |
| Changes the world | yes → re-pin |
| Depends on | 14.3–14.7 |
| Decisions | D-13 (owner): **daily wear by material + repair that costs material; NPCs repair what they use; what nobody uses falls to ruin.** No hard cap on buildings |

## Goal

"Three families should not hold twenty houses" — not because of a cap, but
because every building wears down, repairing costs work and material, and a
band only keeps up what it uses.

## Background (checked on 0.15.160)

- `Building.durability` (~l. 934): `null` until completion, then
  `def.workTicks`; `ruined` when ≤ 0; `soundness` 0–1 for the condition bar.
- `Building.damage(amount)` and `repair(amount)` exist. `repair` is
  **effort only, no materials**, by design (comment ~l. 1150: sabotage repair
  should not need a second granary of thatch). `ActionSystem.doBuild` decides
  when to repair instead of `addWork` (~l. 2860–2880, counter `building_repaired`).
- Wear already exists for **abandoned comarcas only**:
  `abandonedBuildingNeglectPerDay(building, daysPerYear)` in
  `world/ComarcaEcology.ts` (~l. 31) = `workTicks / (daysPerYear × COMARCA_NEGLECT_LIFETIME_YEARS)`.
- `NeedsSystem.shelterAt` already ignores ruins; storage is 0 on a ruin.

## Steps

1. Lifetime per design: optional `BuildingDef.lifetimeYears`. Default from the
   dominant material when absent (R16):

| Materials | lifetimeYears |
|---|---|
| only sticks/thatch (windbreak, lean-to, storage pit lining) | 0.5 |
| mud | 2 |
| wood frame | 4 |
| stone | 10 |
| `natural` (cave), `furniture`, `workTicks 0` | never wears |

2. Shared helper `dailyWear(building, daysPerYear)` in a new
   `sim/systems/Upkeep.ts` = `workTicks / (daysPerYear × lifetimeYears)`.
   Refactor `abandonedBuildingNeglectPerDay` to call it (one formula, not two).
3. Once a day (in the existing daily pass that runs per building — find it),
   every complete structure takes `damage(dailyWear)`. Weather (15.1) will
   multiply this later; leave a parameter for it.
4. Repair costs material: repairing from soundness `s` to 1 costs
   `ceil((1 − s) × 0.25 × def.materials[k])` of each material `k` (R16),
   delivered to the building like construction materials, then effort as
   today. Rewrite the comment above `repair` to state the new contract and why
   (owner decision 2026-10-16). Sabotage repair uses the same path.
5. Who repairs (new module `ai/Upkeep.ts`, hook in `Brain`, R14): a person
   scores `repair` for a building **they used** in the last 5 days (slept in,
   stored in, worked at — record `lastUsedDay` on the building when used) with
   soundness < 0.6. Score grows as soundness falls. Gather materials through
   the same `gather_for_site` path (2.15).
6. Ruin and removal: a ruin nobody repairs for one season (`daysPerSeason`)
   is removed and leaves a pile with 25 % of its materials (rounded down).
   Chronicle line for the band; insight at the place (R6).
7. UI: the building panel shows condition and "needs repair" when < 0.6; a
   ruin says why it is a ruin.
8. Counters: `building_worn`, `building_repaired` (exists), `building_ruined`,
   `ruin_removed`, `repair_materials_spent`.

## Tests

- Unit: a lean-to unused for one year becomes a ruin and then disappears,
  leaving a pile; a used mud hut whose household repairs it stays sound.
- Unit: repair consumes materials in proportion to damage.
- Unit: a cave never wears.
- Round trip: `lastUsedDay` and durability survive save/load (R11, R24).
- Sim: in `band` (1 year), report buildings per household at the end of each
  season and the counters; there must be no monotonic growth of buildings per
  household beyond what is used.

## Done when

Tests pass; re-pinned; counters reported.

## Watch out

- A band whose shelter falls to ruin in winter can die: that is the design,
  but measure cold deaths before/after and report them.
- Never add a cap on the number of buildings.
