## Goal

Right-click → "Work on…" an unfinished site: the worker goes and fetches what
is missing, piles it at the site, and only then builds, until 100 %. A hearth
placed by the player with empty hands gets finished without further orders.

## Background (checked on 0.15.160)

- `ActionSystem.doBuild` (~l. 2884): if `!site.materialsReady` and the worker
  carries something the site wants → `haul`; otherwise
  `abandon(person, 'site_needs_materials')`. There is still no "go and fetch"
  branch inside the action.
- M15 (changelog 2026-10-15, "conservar las obras del jugador y reanudar tras
  reunir materiales"): an ordered worker becomes a backer of the site, so after
  the abandon the **scorer** can offer `gather_for_site` and then the same site
  again. Test in `orders.test.ts`. This may already satisfy N40 for NPCs ordered
  by the player — but not for the **directed player character**, whom the
  scorer does not drive.
- `BUILDINGS.hearth` needs sticks and flint (check the exact `materials`).

## Steps

1. Capability tests (separate files, hand-built world, no randomness):
   - `m16-hearth-buildable.test.ts`: a band with the hearth's materials on the
     ground nearby places a hearth, one person is ordered to work on it, and
     it reaches 100 % within a bounded number of steps; `progress` never
     decreases. Variant: same with **no** materials stacked (only lying around).
   - `m16-work-on-fetches-materials.test.ts`: "work on" a site without its
     materials → the worker carries the missing ones to the site pile and only
     then `progress` rises; counter `gather_for_site` > 0. Run it both for an
     NPC given the order and for the directed player character
     (`sim.autonomy === 'manual'`).
2. Run both. Whatever passes is a regression test (R22).
3. If the player-character variant fails: when "work on" is ordered and the
   site lacks materials, queue the fetch inside the order instead of
   abandoning: reuse the existing `gather_for_site` selection logic (find it
   with `grep -n "gather_for_site" src/sim/ai/Brain.ts src/sim/systems/ActionSystem.ts`),
   extracted into a shared helper if it lives inside `Brain`. Never write a
   second "find the material" search.
4. If no material can be found in sight or in memory, abandon with a **new,
   specific** reason (e.g. `site_material_unavailable`, text "Nobody knows where
   to find {item}") via the existing `STOP_REASONS` path (R6, R7).
5. Spanish names (D-11): in `src/i18n/es/data.ts` change `"Hearth": "Hogar"` to
   «Hoguera» and `"Fireplace": "Hogar interior"` to «Hogar». Ids unchanged.
   Add test `m16-hearth-name`: every visible Spanish string that named the
   outdoor hearth now says «hoguera» (search the `es` tables for "Hogar").

## Tests

The three tests above; `orders.test.ts` still passes.

## Done when

All pass; the player can order "work on" a fresh hearth and it gets built.

## Watch out

- The fetch loop is a long action: it must check `interruption()` and its
  progress lives on the site (`delivered`), not on the person (R4).
- Changing the build path changes NPC worlds too → re-pin and say so.
