## Goal

"Pick up" on a distant pile makes the character walk to it before anything
moves into the inventory, like every other verb.

## Steps

1. Test: player 10 tiles from a pile, orders "pick up" → after 1 tick the
   inventory is unchanged and the character is moving; on arrival the items
   move.
2. If it fails: in `ActionCatalog.ts` `case 'pile'` and in the action that
   calls `Simulation.takeFromPile`, require reach (reuse the reach helper other
   verbs use — `grep -n "reach\|inReach\|REACH" src/sim/systems/ActionSystem.ts`);
   out of reach → walk first.

## Done when

The test passes (or R22: already fixed).

## Result (2026-10-20) — verified already fixed

`m16-pickup-reach` passes on current code. The ordered action checks capacity,
sets the pile as its target, and calls `travel` before `takeFromPile`. With the
travel call temporarily disabled, the capability test fails because the item
is already in the inventory after the first tick; restoring the call makes it
pass. R22 therefore records the behavior as already fixed by M15 `3b8a57b`
(2026-09-11). No game code changed, and the seed baseline was not re-pinned.

Typecheck passes. The before area run (`band`) had one known failing check,
`perf-budget` (546 steps/s, floor 1,678); no after simulation run was needed
because the phase made no world change. No screenshot: the UI did not change.
