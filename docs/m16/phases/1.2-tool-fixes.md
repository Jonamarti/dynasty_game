## Goal

`npm test` and `npm run e2e` finish by themselves with exit code 0, twice in a
row, on this Windows machine; CI stops ignoring failures.

## Background (checked on 0.15.160)

- `.github/workflows/ci.yml:29` and `deploy.yml:40` have `continue-on-error: true`.
- `playwright.config.ts` `webServer` runs `npm run dev -- --port <PORT>
  --strictPort` with `reuseExistingServer: true`. Every e2e run at the M15
  close printed all cases `ok` and then hung at teardown (an orphaned Vite on
  Windows) — see `docs/m15_closeout_20261016.md`.

## Steps — one commit per entry

Common recipe: reproduce → understand → fix → run twice.

| Entry | What to do |
|---|---|
| T1 | `npm.cmd run sim:check -- --scenario tiny` reports 11 failures with 0 steps while the matrix passes it. Compare how `tools/headless.ts` and `tools/scenarios.ts` start a scenario; 0 steps means it never ran. Fix the tool |
| T3 | `band.test.ts`, `herding.test.ts`, `determinism.test.ts`, `grazing.test.ts`: time each alone. If one really needs more than 5 s, give **that test** an explicit timeout with a comment saying why. Never raise the global timeout |

| E16 | `.newgame-option` goes from 3 to 0 after a navigation (1 in 99). Try to reproduce with `--repeat-each=50` on the spec that showed it; if it reproduces, find the race; if not, record the attempt in `docs/bugs.md` and move on |
| T2 | **Last**, once T3/T4 are fixed: remove `continue-on-error: true` from the test steps in both workflows |
