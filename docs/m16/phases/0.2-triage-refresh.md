## Goal

`docs/m16_bugs.md` reflects the code at the M15 close, so that block 2 does
not "fix" what is already fixed and does not miss what appeared after 13-10.

## Background

The triage was written on 05-10 and extended on 13-10. Between 13-10 and the
M15 close several items were fixed (see `docs/changelog.md` entries of 13–16
October): N9 player sites (2.2), work-on gathering materials (2.15, partly),
E7 block advance (2.25b), container slots `equip_belt`/`equip_shoulder`
(2.16, partly), urgent food search (2.17, partly), open-ocean refusal on the
comarca card (D-19 area).

## Steps

1. Read `docs/changelog.md` from the top down to the 2026-10-13 entries.
   For each entry that touches a triage ID (N.., A.., K.., E.., T..), add to
   that row in `docs/m16_bugs.md`: "→ addressed in M15 by <commit/entry>;
   verify in M16 <phase>".
2. For every entry labelled **V** (T9, T10, A5, A9, A10): try to reproduce it
   (a short test or a manual run). Not reproducible → "resolved in M15,
   <commit>". Reproducible → relabel A, B, C or D.
3. Read the sections of `docs/bugs.md` dated after 2026-10-13. For each open
   entry not already in `m16_bugs.md`, add a row to a new section
   "12. Entries after 13-10" with label, phase (an existing card id from
   `docs/m16/README.md` §7, or "new: needs a card") and one-line summary.
4. If an entry needs a new phase, do not invent one: list it under
   "Needs a card" in `docs/m16/doubts.md` for the owner.
5. Update the "**likely done, verify**" notes in README §7 if you find more.

## Done when

No entry in `m16_bugs.md` has label V; every bugs.md entry after 13-10 is
triaged; README §7 notes are current.

## Watch out

Docs-only commit, no version bump. Do not edit game code here even if a fix
looks one line long — the card that owns it will write the test first (R22).
