## Goal

Three owner reports: (N8) "can't pick up a bundle: hands full — but my hands
are empty and there is room"; (N20) "with a bundle and a hide pouch equipped
it 'picks up' and the items vanish from the world"; and two causes found by
reading code (K3, K4). After this phase: the menu and the action refuse for
the same reason with the same text; nothing ever vanishes; a pile whose first
item does not fit still yields the rest.

## Background (checked on 0.15.160)

- **K4.** `ActionCatalog.ts`, `case 'pile'` (~l. 458): the menu enables "Pick
  up" with the aggregate `actor.carrying < actor.carryCapacity` and, if not,
  shows "Your hands are full". The action decides per item with
  `Carry.canTake` / `itemCapacityFor`. Two copies of one rule.
- **N8 cause.** `ITEMS.bundle` declares `hand: { perHand: 1, perArms: 1 }`,
  goes to the `shoulder` slot and holds only `long` items. With one already
  owned, `itemCapacityFor(person, cfg, 'bundle')` = 1, so `canTake` refuses the
  second; the text shown is the generic "hands full".
- **K3.** `Simulation.takeFromPile` (~l. 3152), "take everything" branch:
  `if (room <= 0) break;` — if the first stack in the pile does not fit, nothing
  after it is tried.
- **N20.** Not explained by reading: `takeFromPile` moves with `transferTo`,
  which looks conservative. The loss may be in a later carry reconciliation
  (`equipContainer`, capacity re-check) or in the pick-up route of
  `ActionSystem`. The conservation test decides.

## Steps

1. Capability tests (one file each, hand-built world):
   - `m16-pickup-second-bundle`: empty hands, one bundle in inventory, another
     on the ground → either it is picked up, or the refusal states the true
     cause; never `hands_full`.
   - `m16-pickup-conserves-items`: with bundle and hide pouch equipped, pick up
     N units of **every** item in `ITEMS` that has `container` or `hand`:
     ground + inventory before == after, for each item id.
   - `m16-pickup-rest-of-pile`: pile = [bundle, sticks]; a person who already
     has a bundle picks up the sticks.
   - `m16-pickup-menu-matches-action`: for every item, the menu enables "Pick
     up" iff `canTake(..., 1)` is true; if not, the menu text equals the
     action's refusal text.
2. Run them; keep the passing ones as regressions (R22).
3. Fixes, as the tests demand:
   - K3: `break` → `continue` in the "everything" branch.
   - K4: the menu calls the same per-item predicate as the action. Extract a
     helper `pickUpRefusal(person, itemId): StopReason | null` in
     `core/Carry.ts` used by both (`AGENTS.md`: one helper, not two copies).
   - N8: decide and write in the diary: a second bundle is **carried in the
     arms** (capacity 2 when one is worn — it is a long item) **or** refused
     with "You already carry a bundle on your shoulder". Default if unsure:
     refuse with that reason (smaller change).
   - N20: follow the conservation test to the line that loses items; fix there.
4. New refusal texts go through `t()` with Spanish (R7).

## Done when

All four tests pass; re-pinned; the changelog names the cause of N20.

## Watch out

`takeFromPile` is used by NPCs: the `continue` changes worlds. That is the
point; re-pin and say so.
