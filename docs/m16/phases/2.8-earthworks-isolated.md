## Goal

A moat that fills with water no longer leaves pending tiles unreachable and the
work half-done forever.

## Files

`src/sim/core/Earth.ts`, the earthwork order path (`grep -n "earthwork" src/sim/systems/ActionSystem.ts`),
`World.updateShore`.

## Steps

1. Test: a moat next to the map edge (or a lake) whose pending tiles get cut
   off by water → either the tiles are worked from the reachable bank, or the
   work closes with a visible reason ("the water cut off the rest of the ditch").
2. Implement: when choosing the next tile, allow working a tile from any
   walkable neighbour (not only from inside the trench); if none of the
   pending tiles has a reachable neighbour, finish the site with the reason (R6).

## Done when

The test passes; re-pinned.

## Result — done (2026-10-20)

`doEarthwork` now considers every walkable working bank connected to the
worker before choosing pending dig or pile tiles. If water has cut off all
remaining tiles, it removes the unfinished site, returns delivered goods to
the ground, and reports the reason in the stop notice and insight. The
capability test `m16-earthwork-water-cutoff` passes; it fails with the old
generic `cannot_reach` path. Water cutoffs use a specific explanation; other
unreachable earthworks close with a general reachability explanation. The target is held only while the worker is still
walking, avoiding target oscillation without holding the worker on a project
after arrival. Full Vitest passes. The `diggers` report has an open
`spatial-hash-spreads` finding recorded in `docs/bugs.md`; the earthwork test
itself passes and the scenario completes a ditch. Version `0.16.8-alpha`;
baseline re-pinned.
