## Goal

The player can queue orders: gather, go somewhere, drink… Shift+click adds to
the end; a normal click replaces the queue.

## Files

`systems/ActionSystem.ts` (where an order finishes or is abandoned),
`entities/Person.ts` (the queue), `persistence/EntityRecords.ts`,
`main.ts` (click handling), `ui/Hud.ts`.

## Steps

1. `Person.orderQueue`: up to 5 entries of the same shape the current order
   uses (`person.resume` / the commanded action fields — reuse, do not invent
   a second order format). Plain data; round-trip test anyway (R11, R24).
2. Shift+click appends; normal click replaces (clears the queue then issues).
3. When the current order finishes or is abandoned, start the next — except
   when the stop reason is `under_attack` or a need past its line (in
   `urgent`/`auto` modes; in `manual` 3.1 already removes need stops): then
   **clear the queue with a notice** saying why (R6).
4. The HUD shows the queue (icons + target) and a "clear" button.

## Tests

- Three queued orders run in order.
- An interruption clears the queue with its reason.
- Save/load keeps the queue.
- e2e: shift+click adds, click replaces (add to `scripts.e2e`).

## Done when

Tests pass; screenshot of a queue.

## Watch out

Do not duplicate 3.1's interruption rules: call the same predicate.
