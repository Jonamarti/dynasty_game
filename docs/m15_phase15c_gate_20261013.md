# M15 fase 15c — gate aún cerrado (2026-10-13)

`needs.spoilRate` stays at its default `0`. The declared gate is a paired
economic comparison with mean survival cost no greater than four percentage
points, plus evidence that preservation offsets food loss. The current runs do
not meet that gate.

## Paired cohort: short negative result, not a pass

The same 20 named seeds were run serially on the same build, with only
`needs.spoilRate` changed:

| Command | Steps per seed | Mean survival | Collapsed | Starved adults |
|---|---:|---:|---:|---:|
| `npm.cmd run sim:seeds -- --scenario band --seeds 20 --steps 3000 --set needs.spoilRate=0` | 3,000 | 97.6% | 0/20 | 1 |
| `npm.cmd run sim:seeds -- --scenario band --seeds 20 --steps 3000 --set needs.spoilRate=0.35` | 3,000 | 97.4% | 0/20 | 0 |

Each run took 91.8 seconds. The paired mean difference is −0.2 percentage
points for rate `0.35`, inside the four-point ceiling, but these 3,000 ticks
cover only 12.5 game days (4.375 days of effective decay at that rate). The
cohort reports survival and demographic counters only: `tools/seeds.ts` does
not emit actual spoilage nutrition, preserved meals, or nutrition saved. This
is too short and too indirect to establish either food cost or preservation
benefit, so the small difference is not a gate pass.

An initial `lean` baseline was stopped after six seeds: all had ended at 0–8%
of peak population. The population floor made it unsuitable for a four-point
paired estimate; those partial observations are not cohort results.

## Existing instruments and their limits

`npm.cmd run sim:check -- --scenario salters` completed 2,400 steps (10 game
days) with the fixture's hardcoded `spoilRate=1`. It reported `1/4` winter
meals preserved and band-attributed spoiled nutrition of `724` for the knowing
band versus `1230` for the other band. It also printed that the loss comparison
failed negative verification and made no survival claim. This is one
asymmetric fixture, has no zero-rate arm, and its differences are not causal.
The 480 carrier person-ticks and selector diagnostics describe this same short
window; they do not establish food saved across seasons.

The existing negative control in
`src/sim/__tests__/salters-checks.test.ts` is useful but narrower: it consumes
one real preserved winter meal, then removes preservation recipes and verifies
that the meal still counts as food while preserved-food attribution falls to
zero. `spoilage-sources.test.ts` separately verifies actual removals against
the dry-run counters. Both controls validate attribution/mechanics; neither
measures an autonomous economic benefit. The focused command passed 6/6 tests:

```powershell
npm.cmd test -- --run src/sim/__tests__/salters-checks.test.ts src/sim/__tests__/spoilage-sources.test.ts
```

## What is still needed

A useful next cohort must pair the same seeds over multiple seasons and report
both ends of the economy in the same run: real spoilage nutrition by source and
owner, actual nutrition consumed from preserved outputs, and demographic cost.
Its negative control must remove preservation availability while keeping the
seed, rate, starting supply, and observation window fixed. The short `band`
pair and current `salters` fixture do not supply that comparison. No default,
parameter, or simulation behavior changed; 15c remains deferred.
